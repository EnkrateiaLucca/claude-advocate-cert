Core exam logic

  1. Verify specifics against the source. Model confidence is not evidence.
  2. Match the model and the feature to the task. Faster tier for volume, top tier for hard reasoning.
  3. Anonymize before upload. "Tell Claude not to retain it" is not a control.
  4. Put recurring context in a Project.
  5. Diagnose what changed before rewriting. Change one thing at a time.
  6. Escalate integrations to Developers or Architects, and high-stakes judgments to qualified humans.
  7. Pick the proportionate step that lets the work continue safely.
How items are written: a workplace scenario with a role → a constraint in the stem (audience, cost, volume, data policy) → "most appropriate" or "best fits" → four options. One option is proportionate. Three fail in predictable ways. "Most appropriate" does not mean "most thorough."

D1

Prompting and Task Execution

DESCRIPTION14% · ~8 items · Lesson 02
Objectives (verbatim)
  1. Create effective prompts for business and technical tasks
  2. Apply task decomposition techniques to structure complex requests
  3. Iterate prompts to improve output quality
  4. Adapt prompting strategies based on task type (analysis, research, drafting, brainstorming)

Mental model

Treat Claude as "a brilliant but new employee who lacks context on your norms and workflows." Golden rule: if a colleague with minimal context would be confused by your prompt, Claude will be too. Weak output on the exam usually traces to a prompt a new colleague could not act on.

Prompt anatomy

Role"You are an operations analyst."
ContextWho reads it, why it matters: "VP reads this on mobile before Monday."
Task"List every action item with owner and due date."
Inputs"Use only the attached notes."
Constraints"Under 120 words. No jargon."
Format"Table: Item, Owner, Due, Status."
ExamplesOne filled-in example row or paragraph

Add how to collaborate: "If it isn't in the notes, write 'not stated'." "Push back if my assumptions are wrong." "Tell me what you're uncertain about."

Four principles

  • Concrete limits beat adjectives. "Under 100 words" works. "Be concise" barely moves output.
  • An example is the strongest format signal. Show a filled template.
  • Explain why. A reason generalizes better than "NEVER do X".
  • State the goal and the format. "Three bullets" is a format. "Convince my team the timeline is realistic" is a goal.

Long prompts: separate parts with labels or XML-style tags (<context>, <notes>, <task>, <format>). Long documents: material first, question at the end.

Decomposition and prompt chaining

Sequential steps"First A, then B, then C." Simple flows you trust.
Checkpoint"Stop after step 2 and show me." Later steps depend on a result you must verify.
Prompt chainSeparate prompts, each using the checked output of the last. Multi-part deliverables.
Self-correctionDraft → review against stated criteria → revise.

Decompose when there are several deliverables, dependent steps, or a needed mid-point check. Each step should produce something you can check.

Iteration

Give specific feedback. "Make it shorter" → "Cut the first two paragraphs and end with the ask."

  • Follow up in the same chat when the draft is mostly right.
  • Edit the original prompt when the first prompt was the problem.
  • Start fresh when the chat has gone off track.

Stuck? "Ask me the questions you need answered to write a better prompt." Instruction followed literally but uselessly? Restate the goal.

Strategy by task type

TypeIncludeAvoid
AnalysisData, criteria, reasoning before conclusions, ask for one recommendation"What do you think?" with no criteria
ResearchResearch mode or web search, goals, sections, constraints, checkable sourcesTrusting training knowledge for recent facts
DraftingAudience, purpose, tone, length, format, an exampleGeneric "write a post about X"
Brain­stormingVolume first (20 ideas), then narrow with criteria, turn by turn"The best idea" in one shot

D1 traps

  • "Be detailed", "be concise", CAPITALS: intensifiers add no structure.
  • Regenerate until it works: the cause stays in place.
  • One giant prompt for a multi-part deliverable: decompose.
  • Paste every document "for context": attention is finite, so curate.
  • Bigger model to fix generic output: add context and constraints.
  • Format described in prose when it must match a template: show an example.
  • Repeat an ignored instruction louder: restate the goal.
D2

Output Evaluation and Validation

DISCERNMENT · DILIGENCE21%, the largest domain · ~13 items · Lesson 03
Objectives (verbatim)
  1. Evaluate Claude-generated outputs for accuracy and completeness
  2. Identify hallucinations, inconsistencies, and biases in responses
  3. Apply fact-checking and validation techniques
  4. Determine when human review or additional verification is required
  5. Edit, adapt, refine, and compare outputs for the intended audience
  6. Organize and curate information and select appropriate output formats (artifacts, inline, structured data)

Accuracy and completeness are separate checks

Accuracy: is every statement true per the source of record? Completeness: did the output include everything that matters? An output can be 100% accurate and still fail by omission. You catch omissions only by reading the source.

"Fabrication concentrates in specificity: names, dates, statistics, citations, URLs, quotes." The more precise a claim, the more it needs checking.

Failure types

HallucinationSpecific-looking detail with no basis: cites "Section 8.2" of a rule with seven sections
DistortionA real fact subtly changed: "up to $50,000" → "start at $50,000"
OmissionA material point left out: a legal-hold exemption disappears
InconsistencyContradictions inside one answer, or different answers across runs
BiasOne-sided framing, stereotyped defaults, unsupported group generalizations
SycophancyAgrees with a wrong premise or caves under pushback
Stale knowledgeOut-of-date training facts presented as current

Signals that are not evidence

  • Claude sounds confident, or rates its own confidence high (official Sample 1 rejects this).
  • Claude re-checks its own answer: the check is not independent.
  • Two runs agree: consistency ≠ accuracy. Two runs that disagree are a useful warning.
  • It cites a source: you still have to open it.
  • Polished, formatted, or in an artifact: people check polished output less often.

Fact-checking techniques

Quote first"For each claim, quote the exact supporting sentence."
Cite location"Give the section number for every requirement."
Permission not to know"If the source doesn't say, write 'not in source'."
Restrict sources"Use only the attached documents."
Label unsourced"Mark general-knowledge claims 'unsourced'."
Compare runsSame prompt in fresh chats. Disagreement flags weak claims.
Ground current factsWeb search or Research, then open the cited pages.
Compute exactlyCode execution for arithmetic. You still check inputs.
Source of recordA person reads the original. This is the verification.

Human-review triggers: scale scrutiny to stakes

OutputMinimum check
Brainstorm, draft for yourselfSkim for usefulness
Internal summary others act onVerify names, numbers, dates, quotes
External (customers, press, regulators)Verify specifics + accountable owner reviews before it goes out
High-risk domains*Qualified professional reviews + disclose AI involvement
Decisions about peopleClaude organizes information. A human owns the decision.

*Usage Policy: legal, healthcare, insurance, finance and lending, employment and housing, academic testing, media. A reviewer counts only if qualified, sees the evidence, can stop the work, and reviews before the consequential step.

Adapt for the audience

  • Executive: bottom line first, decision needed, two or three numbers.
  • Practitioner: steps, owners, details, exceptions.
  • Customer or public: plain language, no jargon, reviewed before sending.

Compare drafts against the goal and the reader. Length and polish are weak signals.

Output-format picker

Inline replyQuick answer read once: "Which section covers access logs?"
ArtifactStandalone deliverable to edit, reuse, or share: brief, tracker, dashboard
File creationDownloadable .docx, .xlsx, .pptx, or PDF
Structured dataFeeds another step or spreadsheet: table or CSV with fixed columns

Ask for the deliverable. "Summarize Q3" gets a chat reply. "Turn Q3 into a one-page doc for leadership" gets an artifact.

D2 traps

  • Send it because it was confident or cited a section blind trust
  • Ask Claude to rate or double-check itself fake safeguard
  • Reformat, reword, or add a disclaimer irrelevant fix
  • Verify one claim, assume the rest blind trust
  • Fill a "data unavailable" gap with an estimate blind trust
  • Throw out the whole output for one error over-reaction
  • Legal review of an internal brainstorm over-engineering

Product and Model Selection

DELEGATION12% · ~7 items · Lesson 01
Objectives (verbatim)
  1. Select appropriate Claude product features (Projects, research mode, chat, artifacts)
  2. Differentiate between Claude model types (Haiku, Sonnet, Opus)
  3. Align model selection with task requirements (cost, speed, quality)
  4. Understand and manage context limitations and memory considerations (when to restart, summarize, or persist)

Feature picker

You need to…UseSignal words
Think, draft, brainstorm turn by turnChat"explore", "quick draft", "talk through"
Reuse the same files and instructions across chatsProject"every week", "same format", "team", "ongoing"
Get one current fact fastWeb search"today's", "latest price", "who won"
Produce a cited report from many sourcesResearch (web search on)"comprehensive", "compare vendors", "market scan", "with sources"
Reason hard over material you haveExtended thinking / higher effort"complex logic", "trade-offs", "multi-step analysis"
A standalone deliverable to edit, reuse, shareArtifact"one-pager", "dashboard", "tracker", "share with the team"
A downloadable Word, Excel, PowerPoint, PDFFile creation".docx", "spreadsheet", "slide deck to send" (needs code execution and file creation on)
Multi-step task ending in a finished file, in your folders, or on a scheduleCowork (desktop, paid plans)"every Monday", "in this folder", "finished file"
Write, test, ship softwareClaude Code"code", "repository", "deploy": developer territory, so the Associate escalates

Research is for depth; a quick fact needs web search. Projects are for recurring context. Features combine: a weekly competitor brief can use a Project + Research + an Artifact.

Model picker: learn the tiers and their trade-offs

TierSpeed / costBest forExam cue
HaikuFastest / lowestQuick answers, simple extraction, high-volume routine drafts"hundreds of", "simple", "fast"
SonnetFast / moderateEveryday writing, analysis, multi-step work. The default."typical", "most tasks"
OpusSlower / highestDeep reasoning, complex analysis, hard judgment calls"complex", "nuanced"

Sample 2 logic: faster, lower-cost model for straightforward high-volume work; the most capable model for complex reasoning. Start with Sonnet and move to Opus on evidence. Anthropic's lineup also includes Fable, a newer tier above Opus. The exam guide names three tiers, so answer with Haiku, Sonnet, Opus.

The effort lever

ModelChanges capability and cost
Effort / extended thinkingChanges how thoroughly Claude works before answering. Cost rises. Core capability stays the same.

Too little effort: missed instructions, unfinished work. Too much: verbose, scope creep, slow simple replies. Think in cost per task: one good turn can beat five cheap follow-ups. A bigger model does not fix a missing source, a vague prompt, or a policy problem.

Context window facts

  • Holds your messages, Claude's replies, and uploads. Standard: roughly 500 pages of text.
  • The whole conversation is re-sent every turn. Long chats cost more and slow down.
  • Attention is finite. Facts buried mid-material get missed. Key instructions go at start and end.
  • Long chats drift. Early rules weaken.
  • Near the limit, claude.ai summarizes earlier messages. Summaries lose detail.
  • Context limit = what fits in one chat. Usage limit = how much you can use over time.

Restart, summarize, or persist

Chat drifted, ignores early rulesRestart with a short summary of decisions and rules
Same task, chat getting longSummarize: handoff summary, check it, carry into a new chat
New, unrelated taskRestart: fresh chat, no old bias
Facts or rules needed across sessionsPersist: Project instructions/knowledge, personal instructions, memory
Sensitive one-off, keep out of historyIncognito chat

Memory and Incognito

  • Claude does not learn from your corrections. A correction lasts only if persisted.
  • Memory is on by default on Free, Pro, Max. Team/Enterprise owners control it. Each Project has its own memory. View, edit, delete in Settings.
  • Search and reference chats (paid plans) looks up past conversations.
  • Incognito: not saved to history, not searched later, still follows org retention. It does not make restricted data safe to upload.
  • Memory is a convenience. It does not replace Project knowledge as a source of truth.

D3 traps

  • Most capable model for everything over-engineering
  • Upgrade the model when facts or context are missing irrelevant fix
  • Research mode for one quick fact over-engineering
  • "Claude will remember last week": only via memory, a Project, or instructions
  • Repeat the format rule louder in a 60-turn chat: restart and persist
  • "Incognito means the data is approved" fake safeguard
  • One long chat for everything: costs more, drifts

Workflow Integration and Solution Design

DELEGATION16% · ~10 items · Lesson 04
Objectives (verbatim)
  1. Apply Claude to analyze requirements and use cases
  2. Leverage Claude for research, planning, and process optimization
  3. Use Claude to support solution design, development, and iteration
  4. Integrate Claude into existing workflows to augment or redesign them
  5. Communicate Claude's value and limitations to stakeholders

Requirements first

DeliverableWhat exactly gets produced?
AudienceWho uses it, for what decision?
SourcesWhat data goes in, and is it approved?
SuccessHow will you know it works?

Audit: how often, how long, how standardized, cost of imperfection? Have Claude interview you first.

Where Claude fits

Strong fitWeak fit
Drafting from approved inputsFinal authority on facts
Summarize, categorize, extractAccountable decisions (hire, escalate an account)
Repurpose for formats and audiencesEmotionally sensitive conversations

The delegation map: three buckets

Claude handlesStandardized, documented, repeatable, low cost of error. Spot-check.
Claude assists, human decidesClaude drafts. A person reviews before it counts.
Human handlesHigh stakes, sensitive situations, complex judgment

Decide with reversibility (can you undo it?), stakes (money, reputation, legal, harm), accountability (who answers for it keeps the decision). Keep a human approval wherever an action is hard to reverse or external. Ask whether the step needs to exist before automating it.

Augment or redesign

Augment (start here): same workflow, faster steps. Redesign: steps merge, move, or disappear, once augmenting works, the process is the bottleneck, and Claude has proven reliable.

  1. Pilot one workflow with a small group.
  2. Validate on a known answer (redo a past task).
  3. Measure against success criteria.
  4. Release autonomy gradually.
  5. Turn repeated explanations into Projects, instructions, Skills.

Communicating value and limits

Bounded task"Claude drafts the weekly ticket summary."
Benefit, labeled"We estimate ~2 h/week. We'll measure it."
Limitation"It can miscategorize. We spot-check 10."
Human owner"Dana approves before sharing."
Constraint"No new spend. Changes go through IT."

Avoid "fully automated", "error-free", unmeasured savings. Usage numbers are diagnostics; outcomes prove value.

Know when to escalate

System integrations, pipelines at volume, API, custom connectors or agentsClaude Developer or Architect
Legal, medical, financial, employment judgmentsQualified human professional
Personal or regulated data, new data sourcesLegal, privacy, data owner
New tools, integrations, policy exceptionsIT, security, policy owner

D4 traps

  • "Claude can handle the whole process, start building" blind trust
  • "No, it involves customer data" over-reaction
  • Full autonomy on day one blind trust
  • Roll out to every team at once over-engineering
  • Automate a report nobody reads irrelevant fix
  • Escalate a simple drafting workflow to an Architect over-engineering
  • Adoption numbers as proof of value fake safeguard
  • Promise "fully automated, no errors" blind trust

DESCRIPTION12% · ~7 items · Lesson 05
Objectives (verbatim)
  1. Configure Claude Projects with instructions and knowledge sources
  2. Manage uploaded knowledge and connectors (e.g., Google Drive, Gmail)
  3. Create effective system-level instructions
  4. Inform, maintain, and update Claude configurations, knowledge sources, and instructions

Where each piece of context belongs

You want Claude to…Put it inScope
Follow house rules in every chatOrganization instructions (admin)Whole org
Know you, your shorthand, preferencesPersonal instructionsAll your chats
Behave a set way for one workstreamProject instructionsEvery chat in Project

Instructions say how to behave. Knowledge says what to know. A Skill says how to do a repeatable task. "Projects store knowledge, skills perform tasks."

Project facts that show up in items

  • Setup: name and description · visibility · instructions · knowledge.
  • Claude does not see the description. A rule typed there has no effect.
  • Context isolation: a file uploaded in one chat stays in that chat. Add it to knowledge for every chat.
  • Retrieval mode: near the context limit, Claude searches Project files and pulls relevant parts. Up to 10x capacity on paid plans, with an on-screen indicator.
  • Name files descriptively: "Travel-Policy-2026-10.pdf".
  • Team/Enterprise sharing: Can view (chat, use knowledge), Can edit (change instructions and knowledge, manage members), Owner.

Effective system-level instructions

Role and context"You draft replies for Acme's Tier 1 support agents."
Source rule"Use only the attached help articles. If the answer isn't there, say so."
Process"Identify the question, find the article, then draft."
Format"Under 150 words. End with one next step."
Conflict priority"If brevity and completeness conflict, keep every required fact and cut background."

Use short labeled sections. Keep it concise: every chat carries it.

Connectors (built on MCP)

  • Claude sees what you see: your account's permissions.
  • Scoped at setup and revocable any time.
  • Gmail send/reply/forward and Drive share/move/trash ask for approval by default.
  • Google Drive works in private Projects only.
  • Team/Enterprise admins enable connectors first. Common pattern: read-only first, write access later with risk-owner sign-off.
  • Google Docs sync to the latest version. Uploaded files do not update.

Test: "Can you access my Google Drive? List three files in the Marketing folder."

Skills and memory

Skills are folders of instructions and resources that load when a request matches the Skill's description. They need code execution and file creation on. Create one by describing the task to Claude. Install custom Skills only from trusted sources.

Memory helps continuity. It is not a source of truth. Keep authoritative facts in knowledge files.

Maintaining configurations

  • Replace superseded documents. Old + new side by side gives mixed answers.
  • Keep 5–10 test questions with known answers. Rerun after every change.
  • Change one thing at a time.
  • Give each shared Project an owner and a review rhythm.
  • Turn repeated corrections into instructions.

D5 traps

  • Put the rule in the Project description irrelevant fix
  • Add the new policy alongside the old fake safeguard
  • Tell users to remind Claude which version to use irrelevant fix
  • Upload in your chat so the team can use it irrelevant fix
  • Connect the whole Drive, tell Claude to ignore HR fake safeguard
  • Store a procedure as a knowledge file irrelevant fix
  • Rebuild the Project from scratch over-reaction
  • Switch to the most capable model over-engineering

Governance, Risk, and Responsible Use

DILIGENCE15% · ~9 items · Lesson 06
Objectives (verbatim)
  1. Identify appropriate and inappropriate use cases
  2. Apply data sensitivity, regulatory, and privacy considerations
  3. Follow organizational AI policies and governance standards
  4. Understand the ethical implications of AI usage
Rule of thumb: make the task safe, then do it. The exam penalizes going ahead unsafely, adding a fake safeguard, and abandoning the task. Sample 3: remove or anonymize customer names and account numbers first, then run the analysis.

Appropriate and inappropriate uses

Claude can handleStandard replies from documented info, reformatting, summarizing your notes, brainstorming. Delegate, then spot-check.
Claude assists, human decidesCustomer letters, survey analysis, a hiring rubric. A person reviews and owns it.
Human handlesDecisions about a person's job, pay, health, credit, or legal standing; sensitive conversations.

High-risk (Usage Policy): legal, healthcare, insurance, finance and lending, employment and housing, academic testing and admissions, media and journalism. Requires a qualified professional in the loop and disclosure of AI involvement. Consumer chatbots must tell users they are talking to AI.

Data sensitivity: before you upload

  1. What kind of data? Public, internal, confidential, regulated personal data.
  2. What does org policy allow for this data class and tool?
  3. What does the task need? Usually patterns. Rarely names.
RemoveDrop unneeded columns (name, email)
ReplaceAC-40021 → C001. Keep the key on your machine.
Generalize2025-02-11 → 2025-02
Scrub free textComments hide names, order numbers, places
Rare combos"Only Enterprise customer in LATAM" still identifies

Fake safeguards

  • "Upload it and tell Claude not to retain it." The data already left your hands.
  • "Use an Incognito chat." Org retention still applies, and the data was shared.
  • "It's internal" or "Legal asked for it." Purpose and seniority do not override policy.
  • "Add a disclaimer." Wrong or non-compliant content stays wrong.

Plan data handling (admins set it, you follow it)

PlanTraining on chatsNotes
Free, Pro, Max (consumer)You choose in Privacy SettingsAllow: kept up to 5 years. Opt out: 30-day standard retention. Paying does not change the choice.
Team, Enterprise, Education, API (commercial)Not used by defaultEnterprise custom retention (30-day min). Admins control memory and connectors.
Incognito (all)Same as planNot in history or memory. Org retention still applies.

Terms change. Verify on Anthropic's privacy pages.

Following org AI policy

  • Use the approved workspace for work data, even when a personal account looks faster.
  • Missing something? Ask the policy owner. Don't work around it.
  • Claude declines and explains why: treat it as information. Don't rephrase to slip past it.
  • See a policy-practice gap? Report it and help make the approved path easier.

Ethics

  • Bias: coded job-ad language ("digital native"), one-sided framing. Ask Claude to review, then review yourself.
  • Fabrication: never invent testimonials, reviews, quotes, or data.
  • Accountability: whoever sends or files the work owns it.
  • Disclosure: when it changes how people judge the work, when required, and always in high-risk cases. Diligence statement: what AI helped with · which tool · what you reviewed · what you changed · who is responsible.
  • Constitutional AI training reduces risk. It does not replace your judgment.

D6 traps

  • Upload as-is, the analysis is internal blind trust
  • Upload and tell Claude not to retain fake safeguard
  • Skip the analysis / ban AI for the team over-reaction
  • Let Claude make the hiring decision blind trust
  • Anonymize, then let Claude decide fake safeguard
  • Personal Pro account with training off fake safeguard
  • Escalate every request to Legal over-engineering

Troubleshooting and Optimization

DISCERNMENT10% · ~6 items · Lesson 07
Objectives (verbatim)
  1. Identify, diagnose, and resolve issues with underperforming prompts or poor outputs
  2. Adjust approach based on feedback and results
  3. Optimize workflows for efficiency and effectiveness

Troubleshooting checklist: run in order

  1. What changed? Knowledge files, instructions, model or effort, connector, input file, person running it.
  2. Context? Source attached? Fact buried in a long chat? Drift? Context a teammate supplies that you don't?
  3. Instructions? Goal stated? Concrete limits? Conflicting rules?
  4. Model and settings? Light model on hard reasoning, or top model at max effort on routine work?
  5. Source of facts? Attached or connected source, or general knowledge?

Change one thing at a time. Rerun the same 5–10 test inputs with known-good outputs after each change.

Adjust on feedback

  • Turn "too long" into "cut the background, keep the three figures".
  • Steer early. A quick correction beats a full regenerate.
  • Restart when a chat has drifted far.
  • Weekly corrections → instructions. Repeated explanations → a Skill.
  • The model does not learn from you.

DAY

Exam strategy, logistics, and the 4-week plan

Lesson 08

Time budget: three passes

Pass 1 · 0–80 minAnswer every item in order. Past ~2 min: best answer, flag, move on. No blanks.
Pass 2 · 80–110Flagged items. Reread for the constraint. Change only with a named reason.
Sweep · 110–120No blanks. Each multiple-response item has exactly N picks.

Checkpoints: item 15 ≈ 20 min · 30 ≈ 40 · 45 ≈ 60 · 60 ≈ 80.

Multiple-response tactic

  • Read the count first. Select exactly that many.
  • Judge each option alone: true, and does it answer this stem?
  • Treat every item as all-or-nothing. No official source confirms partial credit.
  • Reject near-duplicates and options true in general that miss the scenario.

"About a quarter of items are multiple-response" is an unofficial community estimate.

How to read an item

  1. Read the question line first ("best first step", "Choose TWO").
  2. Find the constraint: privacy, stakes, cost/volume, recurrence, recency.
  3. Predict the answer with the core logic, then eliminate by pattern.
  4. Choose the proportionate step that keeps work moving safely.

Tie-breakers: the option a careful professional could defend to the risk owner · fix the cause over a per-chat workaround · distrust "always", "never", "guaranteed", "fully automatic".

Register, ID, reschedule, retake

  • Register: Partner Academy (partner email) → pay → schedule with Pearson VUE. Get accommodations approved first (allow 10+ days).
  • ID: government photo ID; name must match exactly. Fix it ≥24 h ahead via certifications-support@anthropic.com, subject "Name Correction Request".
  • Reschedule/cancel ≥48 h ahead. Refunds need an email to support. No-show or late = fee lost.
  • Online: system test, clear desk, no phone, watch, or second monitor, stay in webcam view. Accept the NDA.
  • Retakes: 14 / 30 / 90 days; max 4 per rolling 12 months; fee each time. Renewal: free and on time; lapsed = full exam.

Self-assessment formula

Score each of the 30 objectives: 0 can't explain · 1 can explain · 2 done it with guidance · 3 do it routinely and can say why wrong answers fail.

Priority = (3 − domain average) × domain weight

D2 at 1.5 → 1.5 × 21 = 31.5. D7 at 1.0 → 2 × 10 = 20. D2 comes first. Ready to book: ≥2 on every objective, 3 on most of D2, a steady practice score a week apart. Practice bands (uncalibrated): 45–50 strong · 38–44 close · 30–37 keep studying · <30 restart.
